## After the hardware session (2026-11-02)

Andrea ran the hardware discovery session (#3) on 2026-10-29 and 2026-11-02; every finding, with its log, is in [hardware-session-2026-10-29.md](research/hardware-session-2026-10-29.md). Folded into the code and docs on 2026-11-02 (PR "Fold the hardware session into the code"). Below, what is now answered and what is still open.

### Answered

- **Global Channel**: only the dev equal to the Global Channel answers; dev 15 is shown as G.16 (`kShownGlobalChannelOfDev0` holds).
- **Slot reads (#4)**: type 14 spec 0–3 reads each Slot's Edit Buffer, and the reply follows the requested Slot (`kSlotEditBufferReplyFollowsRequestedSlot` holds). Type 10 never answers.
- **Bank requests (#12)**: request type = dump type + 14 (15–24 for the Banks shown as 0–9); SysEx Bank 1 = Bank shown as 0. Bank reading and writing are verified: `kBankReadingVerified = true`, `kBankRequestTypeOfSysExBank1 = 15`. The memory writer now backs up every Bank before overwriting it and reads every write back; the "no backup possible" path stays for tests only.
- **Type 20 is not an All Controllers Request on the 2X**: it reads a Program of the Bank shown as 5. The Connection check no longer sends it; it tests CC transmission by asking the user to turn a knob, as its last step. The decision "Does C off also block the CCs answering an All Controllers Request?" (#9) is moot.
- **CC values (#6)**: switches send 1 and any non-zero is on (the editor's 127 works); stepped CCs send small indexes equal to the SysEx value; CC35 is 0–3 as assumed (`kRingModReachableByCc35` holds); CC78 is unscaled 0–120. Filter Type order verified. **LFO2 Dest/Arp Mode was wrong** and is fixed: 0 Arp Down, 1 Arp Up, 2 Arp Up/Down, 3 LFO Amp, 4 LFO Osc 1+2, 5 Arp Random, 6 Arp Echo, 7 LFO Filter; range 0–7, no "off" (the DAW parameter "X: LFO2 Dest/Arp Mode" now has 8 steps instead of 9).
- **Type 0 Program dumps (#7)** are applied at once and audibly, even during a held note. Pacing: 0–50 ms between dumps worked; 600 dumps 50 ms apart while Live played through the same MIDI output caused no problem. `kProgramDumpIntervalMs = 100` is conservative.
- **Performance Edit Buffer (#5)**: type 40 reads it live (unstored panel changes included), type 41 reads stored Performances. **A type 30 dump is stored but not applied** (`kPerformanceEditBufferDumpIsApplied = false`): editing Performance settings from the editor does not change what the synth plays, and a Slot Channel edited in the editor is not followed by the synth. Since 2026-11-03 the Performance tab therefore shows those settings read-only with a note saying why, and the engine refuses Performance edits (`RefusedNotApplied`), DAW automation included, until a way to apply them is found (#31); the manual Slot Channel overrides, which send nothing, stay editable. Project recall (#8) still restores the Slots' sounds, through its type-0 dumps (`kProjectRecallSendsSlotDumpsAfterPerformance` is now known to be necessary), but not the Performance settings.
- **Probe**: Save log starts in `~/Documents/Nord Lead 2X/logs/` and remembers the last folder; the Bank scripts take the Bank as the panel shows it (0–9) and derive the dump and request types from it.

### Open

- **Live Performance editing (#5)**: how to make the synth apply Performance settings sent from the editor (#31).
- **Why Programs 1–4 and 17 of Bank 0 became empty**: the editor sent only read requests that day, and the only code that writes Banks (the Probe's write scripts) used dump type 4 and Bank 3 read back unchanged. Reread all Banks later and compare with factory to see whether it happens again (#32).
- **Which Bank a Bank Program dump lands in**: the one named by its type byte or the one selected on the panel? Every write so far had both the same. Until known, the memory writer keeps both naming the target Bank.
- **Kits**: Kit Bank locations (spec 99–108) answer, but with contents that change from read to read and match no factory Kit, and a Kit written as type 1 spec 99 did not read back. Reading and writing Kit Banks is unknown (#33). Also: a type 14 read of a Slot holding a Kit is unreliable, because the reply's format follows the active Slot; the editor still tells Kits apart by reply size, which is right only for the active Slot (`kSlotEditBufferReplyFormatFollowsActiveSlot`; #33).
- **Performance Bank writes**: a type 31 dump in Program mode changed nothing; Performance mode is untested (#34). Bytes 648–653 of a Performance dump change between reads.
- **Not yet checked**: whether a type 0 dump cuts held notes for a Performance dump (moot while it is not applied); the LED names of value 0 for the stepped controls other than Filter Type and LFO2 Dest/Arp; reverse CC sweeps; C off and the knob prompt.
