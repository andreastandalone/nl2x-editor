# Toolchain

On 2026-10-28:

- Development Mac: Intel x86_64, Xcode 26.3, CMake 4.4 (Homebrew), no Ninja. Homebrew builds from source here, so heavy brew installs are avoided; dependencies come through CMake `FetchContent` at pinned versions.
- **JUCE 9.0.4** (released 2026-10-12, AGPLv3 dual licence confirmed in its LICENSE.md). Chosen over 8.0.12 for Xcode 26 support.
- **Catch2 v3.9.1** for tests.
- **pluginval v1.0.4** (macOS zip from GitHub releases), downloaded into the session scratchpad, never into the repo.
- Universal builds: `CMAKE_OSX_ARCHITECTURES="arm64;x86_64"`; only x86_64 can run on this Mac. CI on GitHub's arm64 macOS runners runs the tests on Apple Silicon.
- 2026-10-28 (#2): inside the agent sandbox, CMake's own downloader times out on github.com while `curl` works. Workaround: fetch the tarballs with `curl` into a directory and pass it as `-DNL2X_DOWNLOAD_CACHE=<dir>` (files named `v3.9.1.tar.gz` and `9.0.4.tar.gz`, as in the URLs); CMake checks the hash and skips the download. CI downloads normally.
- 2026-10-28 (#2): a clean Universal Release build of the plugin takes several minutes on the development Mac; engine-only builds (`-DNL2X_BUILD_PLUGIN=OFF`) take seconds.
- 2026-10-28 (#3): the engine-only build directory `build/engine` lies inside the full build's tree, where the full build also puts its `engine/` subdirectory, so `ctest --test-dir build` runs every test twice (110 = 2 × 55). Harmless; use `ctest --test-dir build/engine` for the real count, or another directory name for the engine-only build.
- 2026-11-02 (#3 follow-up): the dependency tarballs live in the gitignored `.local/deps/` of the repository (`9.0.4.tar.gz`, `v3.9.1.tar.gz`), and every build uses them: `cmake -S . -B build/main -DCMAKE_BUILD_TYPE=Release -DNL2X_DOWNLOAD_CACHE="$PWD/.local/deps"`, then `cmake --build build/main -j2` (`-j8` gets killed on the development Mac). Never point the cache at a temp folder or a session scratchpad: it disappears and the next configure tries the network again. Scratch work and raw Probe logs also go under `.local/` (`.local/hardware-logs/`, `.local/backups/`, `.local/tools/`), never in `/tmp`. This supersedes the scratchpad cache of the 2026-10-28 entries above.
- 2026-11-02 (CI speed-up): `ci.yml` builds through **ccache** (Homebrew, wired with `CMAKE_C_COMPILER_LAUNCHER`/`CMAKE_CXX_COMPILER_LAUNCHER`), its directory `.ci-cache/ccache` persisted with `actions/cache` under a new key per run (`ccache-macOS-<ref>-<run id>`) and restored by prefix, falling back to main's. The step "ccache statistics" shows the hit rate. `release.yml` deliberately builds without it: a release is rare and should come from a clean compile. Before ccache a CI run took 11–25 min. On PR #36: 11 min 05 s with an empty cache, 5 min 19 s warm (build step 8:55 → 3:36, 99 % hits; what is left is mostly LTO linking). The cache is about 0.1 GB.
